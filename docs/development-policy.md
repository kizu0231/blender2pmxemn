# 開発方針

## 基本方針

- まずは既存機能を Blender 5.1 上で継続利用できる状態にすることを優先します。
- 大きなリファクタや CI の再設計は、既存機能の動作を妨げない範囲で段階的に進めます。
- fork 元への追従と本リポジトリ独自の改修を両立できるよう、変更は小さく分けて管理します。

## 優先順位

### 第1優先: 既存機能の Blender 5.1 対応

- アドオン有効化
- PMX import / export
- XML 作成と連携
- テンプレート追加
- 主要なボーン・ウェイト関連ツール

### 第2優先: round-trip 品質の改善

- モデル名の保持
- 剛体・ジョイント情報の保持
- 材質モーフの保持
- テクスチャの相対パス化とコピー

### 第3優先: 保守性の改善

- `__init__.py` など大きなモジュールの整理
- Blender 5.x 互換処理の集約
- CI の改善
- `uv` の導入検討

## ブランチ運用

- 通常の機能改修は `develop` から feature ブランチを切って進めます。
- Blender 5.1 対応の本線も `develop` に集約します。
- 破壊的なリファクタや CI の大規模変更は、必要になった段階で専用の長命ブランチを切って進めます。

## `master` ブランチの扱い

- `master` は fork 作成時に残る旧ブランチで、現在の運用上の主ブランチではありません。
- 本リポジトリでは `main` / `develop` を主に使います。
- `master` は混乱を避けるため、最終的には削除を検討します。
- ただし、既存の参照や外部リンクの確認が済むまでは、互換のために一時的に残しても構いません。
